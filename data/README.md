# Dataset

## What it is

The dataset is a spatio-temporal collection of tomato plant images. It has **12,119 RGB images** of **200 individual plants**, each rated by a plant-physiology expert on a five-level health scale.

| Item | Detail (from the paper) |
|---|---|
| Site | Fruit Vegetable Research Institute, Buyeo, South Korea, in semi-open greenhouses |
| Period | Jan–Jul 2022 (Lines 2–3) and Aug–Dec 2022 (Lines 1 and 4) |
| Varieties | Nonari-Cherry (Line 1), Amos Coli (Lines 2 and 3), Dafnis-Hybrid (Line 4) |
| Plants | 50 per line, 200 in total |
| Visits | Weekly: 25 weeks for Lines 2–3, 18 weeks for Lines 1 and 4 |
| Views | 3 per plant per visit (left, right, top), focused on the upper plant region |
| Camera | Smartphone cameras, with a colour checker in the scene |
| Plant ID | A QR tag on each plant (plant number, slab number, cultivation period) |
| Labels | Expert health level 1–5 (see below) |

| Level | Category | Indicators (Table 2) |
|---|---|---|
| 5 | Optimal health | Vibrant green leaves, uniform growth, no visible stress, disease, pests or deficiencies |
| 4 | Minor deviations | Slight discoloration, minor leaf curling/wilting, early nutrient imbalance, small pest presence |
| 3 | Moderate health | Noticeable yellowing/browning, leaf deformation, moderate pest/disease symptoms, stunting, some necrotic spots |
| 2 | Poor health | Extensive discoloration, widespread necrosis, severe infestation, stunting, significant wilting or leaf drop |
| 1 | Very poor health | Severe leaf damage or defoliation, major necrosis, severe stunting, plant near death |

Images per level (Table 3):

| Line | Class 1 | Class 2 | Class 3 | Class 4 | Class 5 | Total |
|---|---:|---:|---:|---:|---:|---:|
| Line 1 | 18 | 27 | 756 | 1,412 | 341 | 2,554 |
| Line 2 | 9 | 21 | 324 | 1,743 | 1,509 | 3,606 |
| Line 3 | 30 | 450 | 933 | 1,266 | 889 | 3,568 |
| Line 4 | 27 | 22 | 73 | 504 | 1,738 | 2,364 |
| Total | 84 | 520 | 2,086 | 4,952 | 4,477 | 12,119 |

## How to obtain it

The dataset is **not publicly available** because it is part of an ongoing project. To request access, email **afuentes@jbnu.ac.kr** (Data availability statement of the paper).

## Expected layout

```
data/
├── annotations.csv          # one row per image (you create this from the delivered data)
├── images/                  # image files; paths in annotations.csv are relative to this folder
│   ├── line1/...
│   ├── line2/...
│   ├── line3/...
│   └── line4/...
└── splits/                  # generated by scripts/prepare_splits.py
    ├── class_distribution.csv
    ├── random/line{1..4}/{train,val}.csv, classes.json
    └── plant/line{1..4}/{train,val,test}.csv, classes.json
```

`annotations.csv` must have these columns:

| Column | Type | Meaning |
|---|---|---|
| `image_path` | str | path relative to `data/images/` |
| `line` | int | cultivation line, 1–4 |
| `plant_id` | str/int | plant number within the line (from the QR tag) |
| `week` | int | weekly visit index within the cultivation period |
| `view` | str | `left`, `right` or `top` |
| `health_level` | int | expert level 1–5; use `0` for a dead plant (used only for the Figure 11 trajectories) |

Example:

```csv
image_path,line,plant_id,week,view,health_level
line1/P005/W03_left.jpg,1,5,3,left,4
line1/P005/W03_right.jpg,1,5,3,right,4
line1/P005/W03_top.jpg,1,5,3,top,4
```

> The column layout is a convention of this repository. The paper describes the information that was recorded but not a file format. Any folder structure works as long as `annotations.csv` points to the files.

## Pre-processing performed by `scripts/prepare_splits.py`

1. Images with level 0 are removed.
2. **Class filtering (Sec. 3.1.1):** health classes with too few samples are removed per line. The paper says "fewer than 30 samples"; Figure 5C shows Line 3 without Class 1, which has exactly 30 images. For this reason the default drops classes with **≤ 30** images (`data.exclude_at_threshold: true`). The classes that remain are:
   - Line 1: Classes 3, 4, 5
   - Line 2: Classes 3, 4, 5
   - Line 3: Classes 2, 3, 4, 5
   - Line 4: Classes 3, 4, 5
3. **Random protocol (Tables 4, 6, 7):** an image-level random 80:20 train/validation split. It is stratified by class by default; the stratification is an assumption.
4. **Plant protocol (Table 8):** 70% / 20% / 10% of *plants* go to train / validation / test, so no plant appears in two subsets.

The script prints and saves the class distribution of your local copy, so you can check it against Table 3.

### Note on split sizes

Table 4 of the paper reports these train + validation totals: Line 1 2,509, Line 2 3,575, Line 3 3,547, Line 4 2,315. Removing the filtered classes from Table 3 gives 2,509, 3,576, 3,538 and 2,315. Lines 1 and 4 match exactly. Lines 2 and 3 differ by 1 and 9 images. The exact per-image split used in the paper is not available, so a re-created split will not be image-for-image identical to the original.
